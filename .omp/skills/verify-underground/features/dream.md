# Nightly dream

Every night at 04:00 launchd runs `code/agent-dream` as `ugagent`, with stdout and stderr appended to `root/logs/agent-dream.log`. The dream collects the agent's session transcripts and mnemopi memory rows written since the last good dream into a digest, asks omp (non-interactive, no session) to review them, and saves the answer as a dated report in `~/.omp/agent/dreams/`. A good report moves the window forward; a bad one is marked with a `Failure:` line and the window stays. The owner learns the result as a notice at the next `omp` launch.

## Sub-features

- `dream-skip` skips with exit 0 and leaves no run dir when nothing happened since the window start.
- `dream-ok` writes the report, the digest with the session text and `.state`, and calls omp with the fixed review flags.
- `dream-memory` puts new mnemopi memory rows in the digest and keeps a `.mnemopi-before.db` copy.
- `dream-nosummary` fails when the answer has no `Summary:` line; the report gets a `Failure:` line and `.state` stays.
- `dream-omp-fail` fails when omp exits non-zero, with the same report and `.state` rules.
- `dream-lock` skips with exit 0 when another dream holds the lock, and runs again once it is free.
- `dream-notice` shows the result at the next owner launch: `dream: <summary> ...` after a good dream, `the last dream failed: ...` after a failed one.

## How to get to it (user POV)

- launchd starts `/Library/Underground/code/agent-dream` as `ugagent` at 04:00 every day (`com.underground.agent-dream`); output goes to `/Library/Underground/logs/agent-dream.log`. In the stand-in, run `code/agent-dream` as the agent.
- The agent reads `~/.omp/agent/dreams/<date>.md` (and `run/<UTC time>/digest.md`, `answer.md`, `omp.err` for detail).
- The owner sees the outcome as a warning notice when they start a session with `omp` (`host/bin/ug-agent`); see [session-start.md](./session-start.md) for the other start notices.

## Driving it with ugv

Preconditions:

- `U=.omp/skills/verify-underground/scripts/ugv`, `RUN=$(date +%Y%m%d-%H%M%S)-dream`, `B=/private/tmp/ugv-$RUN`, `$U up "$RUN"` printed `ready: run=$RUN`, and `$U doctor "$RUN"` ends with `doctor: ok`.
- Fresh baseline: no sessions, no mnemopi db, no `dreams/` dir, empty `root/logs/agent-dream.log`, no `fixtures/omp-answer.md`, no faults.
- Run the bullets in order in one stand-in; each later bullet relies on the state the earlier ones left.

- **Skip.** Run the dream with nothing to review. Run `$U agent "$RUN" --label dream-skip -- code/agent-dream`. Exit `0`, stdout `<now> skipped: no sessions and no new memory rows since <now - 24h>`; the only stub call is `omp config get mnemopi.dbPath`.
- **Skip state.** Run `$U look "$RUN" dream-skip-state -- ls -A agent-home/.omp/agent/dreams agent-home/.omp/agent/dreams/run`. `dreams/` holds only `.lock` and `run`; `run/` is empty (no `.state`, no report).
- **Seed a session.** Write one session with a user prompt and a final answer, and an answer with a summary. Run `$U look "$RUN" dream-ok-dir -- mkdir -p agent-home/.omp/agent/sessions/-work-acme-widget`, then `jq -nc --arg at "$(date -u +%Y-%m-%dT%H:%M:%S.000Z)" '{type:"session",id:"s1",cwd:"/work/acme",timestamp:$at},{type:"message",timestamp:$at,message:{role:"user",content:[{type:"text",text:"please fix the widget build"}]}},{type:"message",timestamp:$at,message:{role:"assistant",stopReason:"stop",content:[{type:"text",text:"fixed the widget build"}]}}' | $U look "$RUN" dream-ok-session -- /usr/bin/tee agent-home/.omp/agent/sessions/-work-acme-widget/2026-11-21T00-00-00-000Z_s1.jsonl`, then `printf '# Dream\n\nSummary: one session, nothing to change.\n' | $U look "$RUN" dream-ok-answer -- /usr/bin/tee fixtures/omp-answer.md`. Each step echoes what it wrote.
- **Dream ok.** Run `$U agent "$RUN" --label dream-ok -- code/agent-dream`. Exit `0`, stdout `<now> ok: $B/agent-home/.omp/agent/dreams/<local date>.md, window <now - 24h> to <now>`. `calls/omp.log` of the step shows `argv=-p --no-session --model default --tools read\,grep\,glob\,retain\,memory_edit --max-time 30m $'You are the dreaming pass ...` with `cwd=$B/agent-home/.omp/agent/dreams/run`, `HOME=$B/agent-home` and `UG_GATEWAY_TOKEN=set`.
- **Dream ok state.** Run `$U look "$RUN" dream-ok-state -- /bin/sh -c 'cd agent-home/.omp/agent/dreams && ls -A . run/* && cat .state *.md run/*/digest.md'`. `dreams/` has `.state`, `<local date>.md` and one `run/<UTC yyyymmddThhmmssZ>/` with `answer.md digest.md omp.err rows.json`; `.state` holds the window end from the ok line; the report is the fixture answer; the digest reads `Sessions with entries in the window: 1; memory rows: 0 (0 new).`, `## Session s1`, `### user ...` `please fix the widget build`, `### assistant final answer ...` `fixed the widget build`, and `None.` under `# Memory rows`.
- **Seed memory rows.** Make the default mnemopi db with one new working and one new episodic row. Run `$U look "$RUN" dream-memory-dir -- mkdir -p agent-home/.omp/agent/memories/mnemopi`, then `$U look "$RUN" dream-memory-seed -- /usr/bin/sqlite3 agent-home/.omp/agent/memories/mnemopi/mnemopi.db "CREATE TABLE working_memory (id TEXT PRIMARY KEY, content TEXT, source TEXT, timestamp TEXT, session_id TEXT, metadata_json TEXT, valid_until TEXT, scope TEXT, consolidated_at TEXT); CREATE TABLE episodic_memory (id TEXT PRIMARY KEY, content TEXT, source TEXT, timestamp TEXT, session_id TEXT, metadata_json TEXT, valid_until TEXT, scope TEXT); INSERT INTO working_memory (id, content, source, timestamp, session_id, metadata_json, scope) VALUES ('w1', 'widget builds need make deps first', 'retain', '$(date -u +%Y-%m-%dT%H:%M:%S.999Z)', 's1', json_object('context', 'ctx w1'), 'global'); INSERT INTO episodic_memory (id, content, source, timestamp, session_id, metadata_json, scope) VALUES ('e1', 'fixed the widget build', 'retain', '$(date -u +%Y-%m-%dT%H:%M:%S.999Z)', 's1', json_object('context', 'ctx e1'), 'global'); SELECT id, timestamp FROM working_memory UNION ALL SELECT id, timestamp FROM episodic_memory;"`. Stdout lists `w1|<now>.999Z` and `e1|<now>.999Z`.
- **Dream memory.** Run `$U agent "$RUN" --label dream-memory -- code/agent-dream`. Exit `0`, stdout `<now> ok: $B/agent-home/.omp/agent/dreams/<local date>-<HHMM>.md, window <previous .state> to <now>` (the dated name is taken, so the report gets the local time suffix).
- **Dream memory state.** Run `$U look "$RUN" dream-memory-state -- /bin/sh -c 'cd agent-home/.omp/agent/dreams && ls -A . && cat .state && cat "$(ls -d run/*/ | tail -n 1)digest.md"'`. `dreams/` now has `.mnemopi-before.db`; the newest digest reads `Sessions with entries in the window: 0; memory rows: 2 (2 new).`, `None.` under `# Sessions`, and `- working_memory id w1 · new · source retain · session s1 · context ctx w1 · <time>` / `widget builds need make deps first`, `- episodic_memory id e1 · new · ... · context ctx e1 · <time>` / `fixed the widget build`; its `# Earlier dream reports` section quotes the first report.
- **Dream ok notice.** Log the ok line as launchd would, then launch as the owner. Run `cat "$HOME/scratch/verify-underground/$RUN"/steps/*-dream-memory/stdout.txt | $U look "$RUN" dream-notice-log -- /usr/bin/tee -a root/logs/agent-dream.log`, then `$U owner "$RUN" --label dream-notice-ok -- host/bin/ug-agent`. Exit `0`, stdout has `omp-stub: warning notice: dream: one session, nothing to change. say "review the dream" to review.`; the step's `calls/omp.log` session call carries the same line in `UG_NOTICES=`. The `ssh` call's `UG_NOTICES` does not have it (the dream notice is added on the agent side).
- **Seed a bad answer.** Add a new entry to the session and replace the answer with one without a summary. Run `jq -nc --arg at "$(date -u +%Y-%m-%dT%H:%M:%S.999Z)" '{type:"message",timestamp:$at,message:{role:"user",content:"why did the build break again"}}' | $U look "$RUN" dream-nosummary-session -- /usr/bin/tee -a agent-home/.omp/agent/sessions/-work-acme-widget/2026-11-21T00-00-00-000Z_s1.jsonl`, then `printf '# Dream\n\nNo summary here.\n' | $U look "$RUN" dream-nosummary-answer -- /usr/bin/tee fixtures/omp-answer.md`.
- **No Summary.** Run `$U agent "$RUN" --label dream-nosummary -- code/agent-dream`. Exit `1`, stdout `<now> failed: the answer has no Summary: line; read $B/agent-home/.omp/agent/dreams/run/<UTC time>/omp.err; the window stays at <.state>`; omp was still called with `-p`.
- **No Summary state.** Run `$U look "$RUN" dream-nosummary-state -- /bin/sh -c 'cd agent-home/.omp/agent/dreams && cat .state && ls -t *.md | head -n 1 && cat "$(ls -t *.md | head -n 1)"'`. `.state` is the same time as after the memory dream; the newest report `<local date>-<HHMM>[-N].md` is `No summary here.` followed by `Failure: the answer has no Summary: line; read .../omp.err`.
- **Failed notice.** Log the failed line and launch. Run `cat "$HOME/scratch/verify-underground/$RUN"/steps/*-dream-nosummary/stdout.txt | $U look "$RUN" dream-notice-fail-log -- /usr/bin/tee -a root/logs/agent-dream.log`, then `$U owner "$RUN" --label dream-notice-fail -- host/bin/ug-agent`. Exit `0`, stdout has `omp-stub: warning notice: the last dream failed: the answer has no Summary: line; read .../omp.err; the window stays at <.state>; read $B/root/logs/agent-dream.log` and no `dream: ...` notice.
- **omp fails.** Set a good answer, make omp exit 3, dream, and clear the fault. Run `printf '# Dream\n\nSummary: would be fine.\n' | $U look "$RUN" dream-omp-fail-answer -- /usr/bin/tee fixtures/omp-answer.md`, `$U fault "$RUN" omp 3` (prints `fault omp: the stub exits 3`), `$U agent "$RUN" --label dream-omp-fail -- code/agent-dream`. Exit `1`, stdout `<now> failed: omp exited 3; read $B/agent-home/.omp/agent/dreams/run/<UTC time>/omp.err; the window stays at <.state>`; `calls/omp.log` shows the `-p` call and `fault omp: exit 3`. Then run `$U fault "$RUN" omp clear` (prints `fault omp cleared`).
- **omp fails state.** Run `$U look "$RUN" dream-omp-fail-state -- /bin/sh -c 'cd agent-home/.omp/agent/dreams && cat .state && cat "$(ls -t *.md | head -n 1)"'`. `.state` is unchanged; the newest report is only `Failure: omp exited 3; read .../omp.err` (the failing omp printed nothing).
- **Lock held.** Hold the lock in the background for 8 seconds, then dream within that time. Run `$U look "$RUN" dream-lock-hold -- /bin/sh -c "/usr/bin/lockf -k $B/agent-home/.omp/agent/dreams/.lock /bin/sleep 8 >/dev/null 2>&1 & sleep 1; pgrep -fl 'lockf -k $B'"` (stdout shows the `/usr/bin/lockf -k ... /bin/sleep 8` pid), then at once `$U agent "$RUN" --label dream-lock -- code/agent-dream`. Exit `0`, stdout `<now> skipped: another dream holds $B/agent-home/.omp/agent/dreams/.lock`, stderr `lockf: $B/agent-home/.omp/agent/dreams/.lock: already locked`; no omp call.
- **Lock state.** Run `$U look "$RUN" dream-lock-state -- /bin/sh -c 'cd agent-home/.omp/agent/dreams && cat .state && ls run'`. `.state` and the `run/` list are as before the locked attempt.
- **Lock released.** Wait for the holder to end, then dream. Run `sleep 8`, `$U look "$RUN" dream-lock-released -- /bin/sh -c "pgrep -fl 'lockf -k $B' || echo 'no lock holder'"` (stdout `no lock holder`), then `$U agent "$RUN" --label dream-lock-after -- code/agent-dream`. Exit `0`, stdout `<now> ok: .../dreams/<local date>-<HHMM>[-N].md, window <.state> to <now>`: the window that the two failures kept is reviewed now.
- **Cleanup.** Run `$U down "$RUN"`. It prints `removed $B` and `evidence: $HOME/scratch/verify-underground/$RUN`.

## Gotchas

- A session counts only if its file changed after the window start and it has message entries with a `timestamp` after the window start. Touching the file or writing entries with old timestamps gives `skipped: no sessions ...`. Append a new entry to retry after a good dream.
- Only `user` messages, `assistant` messages with `stopReason` `stop` or an `errorMessage`, and `toolResult` errors reach the digest. Tool-use turns and successful tool output do not.
- Memory rows and session entries count as new only when their `timestamp` string sorts after the window start (ISO UTC, `.000Z` at the second of the last good dream). The recipes write `.999Z` so a dream in the same second still sees them. Open working rows (no `consolidated_at`, no `valid_until`) from before the window are listed as `open` but do not stop a skip.
- Two dreams in the same UTC second share one `run/<UTC time>/` dir; the second digest replaces the first. Wait a second between dreams when you compare digests.
- The omp stub answers `config get mnemopi.dbPath` with `(not set)`, so the dream always reads the default `agent-home/.omp/agent/memories/mnemopi/mnemopi.db`. A custom db path is not drivable here.
- The report name uses the local date and the times in the log, `.state` and `run/` use UTC. Near midnight they differ (for example report `2026-11-21.md`, run `20261122T035014Z`). Several dreams on one day get `<date>-<HHMM>.md`, then `<date>-<HHMM>-2.md`.
- `$U fault "$RUN" omp N` also breaks the owner launch: `host/bin/ug-agent` exits `N` with no stdout. Clear it before a notice step.
- The owner notice comes from the last line of `root/logs/agent-dream.log` first, then from a `Failure:` line in the newest report. The stand-in never writes the log; append the dream stdout yourself. Without the log line a failed dream should show as `the last dream failed: <Failure text>; read <report>` (covered by `tests/run`, not driven here). A `dream: <summary>` notice shows only when the newest report has no `Failure:` line and is less than 24 h old or has `Status: pending`.
- The ok/failed notices also show `no good backup yet; ...` in a fresh stand-in. That is the backup notice, not part of the dream.
- Hold the lock with an absolute `$B/...` path so `$U down` finds and stops a holder that is still alive. Do not hold it longer than you can wait; a dream started while it is held only logs the skip.
- launchd's schedule, `UserName ugagent` and the log path are not driven here; only `tests/run` checks the rendered plist.
