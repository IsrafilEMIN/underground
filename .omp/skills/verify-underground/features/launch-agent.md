# Start an agent session

The owner types `omp` (setup installs `host/bin/ug-agent` as `~/.local/bin/omp`) to start an omp session as the agent user over the pinned agent sshd. Outside a git checkout the session runs in the agent's `~/scratch`; inside a checkout with a GitHub origin it runs in the agent's own clone `~/work/<owner>/<name>` and `UG_REPO` names the repo. Arguments after `omp` reach the agent's omp unchanged, unsafe arguments are refused before anything connects, the launcher refuses to start when the owner home, the agent key, the agent sshd or the system Remote Login setup is unsafe or broken, and a stale or missing backup shows as a warning notice in the session.

## Sub-features

- `la-outside` outside a checkout: session in `agent-home/scratch`, `UG_REPO` unset.
- `la-repo` inside a GitHub checkout (also from a subdirectory): session in `agent-home/work/<owner>/<name>`, `UG_REPO=<owner>/<name>`.
- `la-args` arguments after `omp` reach omp, through the ssh words after `--` and `agent-session`.
- `la-refused` an argument outside `[A-Za-z0-9._=:/@+-]` (also a space or an empty argument) exits 1 with `refused argument`, before any ssh call.
- `la-session-refusal` the `agent-session: refused argument` exit 64 is not reachable through the launcher.
- `la-backup-none` no `backup/last`: notice `no good backup yet; read <data>/backup/backup.log`.
- `la-backup-old` a `backup/last` older than 2 days: notice `the last good backup is N days old; read <data>/backup/backup.log`.
- `la-backup-fresh` a fresh `backup/last`: no notice.
- `la-mode` owner home not mode 700: exit 1, `is not mode 700`.
- `la-key` agent key missing: exit 1, `no agent key or known_hosts under <data>/agent-ssh`.
- `la-port` agent sshd port does not answer: exit 1, `the agent sshd on 127.0.0.1:<port> does not answer`.
- `la-remote-login` system Remote Login running without the `DenyUsers ugagent` rule: exit 1, `system Remote Login is running, and the system sshd does not deny ugagent` (not reachable on a host that has the deny; see Gotchas).
- `la-no-origin` a checkout with no origin, or a non-GitHub origin: exit 1, `has no GitHub origin, so the agent cannot clone it`.

## How to get to it (user POV)

- Run `omp [ARGS...]` in a terminal outside any git checkout (the owner's `~/.local/bin/omp` symlink to `host/bin/ug-agent`).
- Run `omp [ARGS...]` anywhere inside a git checkout whose `origin` is `https://github.com/<owner>/<name>(.git)`, `git@github.com:<owner>/<name>(.git)` or `ssh://git@github.com/<owner>/<name>(.git)`.
- Run `host/bin/ug-agent [ARGS...]` directly from the kit checkout (same script, same behavior).

## Driving it with ugv

Preconditions:

- Repo root, `U=.omp/skills/verify-underground/scripts/ugv`, `RUN=$(date +%Y%m%d-%H%M%S)-launch-agent`, `$U up "$RUN"`, `B=/private/tmp/ugv-$RUN`.
- `$U doctor "$RUN"` ends with `doctor: ok`. The baseline has no `backup/last` and no repo. Run the bullets in this order; the seed/restore `look` steps keep later bullets on the baseline.
- `look` steps run with the base as cwd, so the paths in them are relative to `$B`.

- **Outside a repo (`la-outside`, `la-backup-none`).** Start omp from the owner home. Run `$U owner "$RUN" --label la-outside -- host/bin/ug-agent`. Exit 0; stdout `omp-stub: session started in $B/agent-home/scratch` and `omp-stub: warning notice: no good backup yet; read $B/owner-home/.local/share/underground/backup/backup.log`. Calls: `launchctl print system/com.openssh.sshd`, `nc -z -w 1 127.0.0.1 9`, then `ssh -tt -p 9 -i $B/owner-home/.local/share/underground/agent-ssh/id_ed25519 ... -o SendEnv=UG_REPO -o SendEnv=UG_NOTICES ugagent@127.0.0.1 --` with notes `UG_REPO=<unset>` and `UG_NOTICES=no\ good\ backup\ yet\;...`; the omp session call shows `UG_REPO=<unset>` and `HOME=$B/agent-home`.
- **Look: scratch dir.** Run `$U look "$RUN" la-outside-state -- ls -d agent-home/scratch`. Prints `agent-home/scratch`.
- **Arguments reach omp (`la-args`).** Run `$U owner "$RUN" --label la-args -- host/bin/ug-agent --model x/y -p hello`. Exit 0, empty stdout (the stub `-p` answer fixture is absent). The ssh call ends `ugagent@127.0.0.1 -- --model x/y -p hello`; the omp call argv is `--extension $B/root/code/ug-notices.ts --model x/y -p hello`.
- **Refused argument (`la-refused`).** Run `$U owner "$RUN" --label la-refused -- host/bin/ug-agent 'a;b'`. Exit 1; stderr `ug-agent: refused argument a;b: only letters, digits and . _ = : / @ + - are allowed`; the step has no stub calls (no launchctl, nc or ssh).
- **Look: nothing started.** Run `$U look "$RUN" la-refused-state -- /bin/bash -c 'tail -n 3 calls/ssh.log; tail -n 3 calls/omp.log'`. The last ssh call is still the `-- --model x/y -p hello` one from `la-args`.
- **Space and empty arguments are refused too.** Run `$U owner "$RUN" --label la-refused-space -- host/bin/ug-agent 'a b'` and `$U owner "$RUN" --label la-refused-empty -- host/bin/ug-agent ''`. Both exit 1 with `ug-agent: refused argument a b: ...` and `ug-agent: refused argument : ...`, no stub calls.
- **agent-session's own refusal (`la-session-refusal`).** Play the sshd directly as the agent. Run `$U agent "$RUN" --label la-session-refusal-direct --env 'SSH_ORIGINAL_COMMAND=a;b' -- code/agent-session`. Exit 64; stderr `agent-session: refused argument a;b`. Then run `$U agent "$RUN" --label la-session-forward-direct --env 'SSH_ORIGINAL_COMMAND=--model x/y' -- code/agent-session` and `$U agent "$RUN" --label la-session-space-split --env 'SSH_ORIGINAL_COMMAND=-p  hello   world' -- code/agent-session`. Both exit 0; omp argv ends `--model x/y` and `-p hello world` (words split on whitespace). Through the launcher this refusal is unreachable: the launcher allows the same characters per argument and refuses whitespace and empty arguments, so every word it sends passes `agent-session`. This is agent-side detail, not a launcher entry point.
- **Inside a GitHub checkout (`la-repo`).** Run `$U repo "$RUN" acme/widget`, then `$U owner "$RUN" --label la-repo --cwd owner-home/code/widget -- host/bin/ug-agent`. Exit 0; stdout `omp-stub: session started in $B/agent-home/work/acme/widget` plus the `no good backup yet` notice. The ssh call note and the omp call both show `UG_REPO=acme/widget`.
- **Look: agent clone.** Run `$U look "$RUN" la-repo-state -- git -C agent-home/work/acme/widget log -1 --format='%H %s'` and, after about 2 s, `$U look "$RUN" la-repo-fetch -- /bin/bash -c 'cat agent-home/work/acme/widget/.git/ug-fetch.status; ls agent-home/work'`. Prints `<sha> seed: first commit`, then `ok <epoch>` and `acme`.
- **From a subdirectory, with arguments.** Run `$U look "$RUN" la-subdir-seed -- mkdir -p owner-home/code/widget/docs`, then `$U owner "$RUN" --label la-repo-subdir --cwd owner-home/code/widget/docs -- host/bin/ug-agent --resume`. Exit 0; session in `$B/agent-home/work/acme/widget`; ssh ends `ugagent@127.0.0.1 -- --resume` with `UG_REPO=acme/widget`. (Run it after the backup bullets and it shows no notice.)
- **Backup 3 days old (`la-backup-old`).** Run `$U look "$RUN" la-backup-old-seed -- /bin/bash -c 'echo $(( $(date +%s) - 3*86400 - 60 )) > owner-home/.local/share/underground/backup/last; cat owner-home/.local/share/underground/backup/last'`, then `$U owner "$RUN" --label la-backup-old -- host/bin/ug-agent`. Exit 0; stdout `omp-stub: warning notice: the last good backup is 3 days old; read $B/owner-home/.local/share/underground/backup/backup.log`; the ssh note `UG_NOTICES=the\ last\ good\ backup\ is\ 3\ days\ old\;...` carries it.
- **Fresh backup (`la-backup-fresh`).** Run `$U look "$RUN" la-backup-fresh-seed -- /bin/bash -c 'date +%s > owner-home/.local/share/underground/backup/last; cat owner-home/.local/share/underground/backup/last'`, then `$U owner "$RUN" --label la-backup-fresh -- host/bin/ug-agent`. Exit 0; stdout is only `omp-stub: session started in $B/agent-home/scratch`. Run `$U look "$RUN" la-backup-fresh-calls -- /bin/bash -c 'tail -n 3 calls/ssh.log'`; it shows `UG_NOTICES=''`.
- **Owner home not 700 (`la-mode`).** Run `$U look "$RUN" la-mode-seed -- /bin/bash -c 'chmod 755 owner-home; stat -f %Lp owner-home'` (prints `755`), then `$U owner "$RUN" --label la-mode -- host/bin/ug-agent`. Exit 1; stderr `ug-agent: your home $B/owner-home is not mode 700; the agent user could read it. Run: host/bin/ug-setup`; no stub calls. Restore with `$U look "$RUN" la-mode-restore -- /bin/bash -c 'chmod 700 owner-home; stat -f %Lp owner-home'` (prints `700`).
- **Missing agent key (`la-key`).** Run `$U look "$RUN" la-key-seed -- /bin/bash -c 'mv owner-home/.local/share/underground/agent-ssh/id_ed25519 owner-home/.local/share/underground/agent-ssh/id_ed25519.away; ls owner-home/.local/share/underground/agent-ssh'` (lists `id_ed25519.away id_ed25519.pub known_hosts`), then `$U owner "$RUN" --label la-key -- host/bin/ug-agent`. Exit 1; stderr `ug-agent: no agent key or known_hosts under $B/owner-home/.local/share/underground/agent-ssh; run: host/bin/ug-setup`; no stub calls. Restore with `$U look "$RUN" la-key-restore -- /bin/bash -c 'mv owner-home/.local/share/underground/agent-ssh/id_ed25519.away owner-home/.local/share/underground/agent-ssh/id_ed25519; ls owner-home/.local/share/underground/agent-ssh'`.
- **Agent sshd not answering (`la-port`).** Run `$U fault "$RUN" nc 1`, then `$U owner "$RUN" --label la-port -- host/bin/ug-agent`. Exit 1; stderr `ug-agent: the agent sshd on 127.0.0.1:9 does not answer. Check it with: sudo launchctl print system/com.underground.agent-sshd. Run host/bin/ug-setup to load it again.`; calls show `nc: fault nc: exit 1` and no ssh call. Then `$U fault "$RUN" nc clear`.
- **System Remote Login running (`la-remote-login`).** Run `$U fault "$RUN" launchctl-print 0`, then `$U owner "$RUN" --label la-remote-login -- host/bin/ug-agent`. The launcher then asks the real `/usr/sbin/sshd -T` of this Mac whether its `/etc/ssh/sshd_config` denies `ugagent`. On a Mac that has the installed deny (as observed: `/etc/ssh/sshd_config.d/010-underground-deny-ugagent.conf`), the session starts: exit 0, `omp-stub: session started in $B/agent-home/scratch`, calls show `launchctl: fault launchctl-print: exit 0` then nc and ssh. On a Mac without the deny, the expected result is exit 1 with `ug-agent: system Remote Login is running, and the system sshd does not deny ugagent; ...` (not observed here). Prove which case you are in with `$U look "$RUN" la-remote-login-sshd -- /bin/bash -c '/usr/sbin/sshd -T -f /etc/ssh/sshd_config -o HostKey=owner-home/.local/share/underground/agent-ssh/id_ed25519 -C user=ugagent,host=localhost,addr=127.0.0.1 2>&1 | grep -i -e denyusers -e error -e denied | head; echo "rc=${PIPESTATUS[0]}"; ls -l /etc/ssh/sshd_config /etc/ssh/sshd_config.d 2>&1'`; observed `DenyUsers ugagent`, `rc=0`. Then `$U fault "$RUN" launchctl-print clear`.
- **Checkout without a GitHub origin (`la-no-origin`).** Run `$U git "$RUN" -- init -q owner-home/code/local-only`, then `$U owner "$RUN" --label la-no-origin --cwd owner-home/code/local-only -- host/bin/ug-agent`. Exit 1; stderr `ug-agent: $B/owner-home/code/local-only has no GitHub origin, so the agent cannot clone it`; only the `launchctl print` call, no nc or ssh. Then `$U git "$RUN" -- -C owner-home/code/local-only remote add origin https://gitlab.com/acme/widget.git` and `$U owner "$RUN" --label la-non-github --cwd owner-home/code/local-only -- host/bin/ug-agent`: same exit 1 and message.
- **Look: no clone made.** Run `$U look "$RUN" la-non-github-state -- /bin/bash -c 'git -C owner-home/code/local-only remote -v; ls agent-home/work/acme'`. Shows the `gitlab.com` origin and only `widget` under `agent-home/work/acme`.
- **Finish.** Run `$U down "$RUN"`; it prints `evidence: ~/scratch/verify-underground/$RUN`.

## Gotchas

- `la-remote-login` depends on the Mac running the verification, not on the stand-in: the launcher always reads the real `/etc/ssh/sshd_config` through the real `/usr/sbin/sshd -T`. On a Mac with Underground installed the deny exists, so the refusal message cannot be reached without editing `/etc/ssh` (out of bounds). Report the refusal as not verified there, and include the `la-remote-login-sshd` look as the reason.
- `la-session-refusal` is only drivable as the agent (`$U agent ... code/agent-session`). Do not report it as verified through `omp`; through `omp` it cannot happen.
- The backup age is whole days, rounded down, and the notice starts above 2 days (172800 s). Seed 3 days plus a margin, as above; the exact 2-day edge was not driven.
- `la-repo` leaves a background fetch running after omp exits. Its `gh pr list` call can be logged under the next step (seen under `la-session-space-split`); read stub calls by their cwd, not only by step. `ugv down` waits for it.
- `$U repo` checkouts are outside any parent repo only because `GIT_CEILING_DIRECTORIES` stops discovery at `/private/tmp`; run owner steps through `$U owner`, never with a plain shell from inside the worktree.
- The `-p` stub answer is empty unless `$B/fixtures/omp-answer.md` exists; an empty stdout for `la-args` is expected.
- Do not delete the key to fake `la-key`: the host guard blocks `rm`. Move it aside and back as shown.
