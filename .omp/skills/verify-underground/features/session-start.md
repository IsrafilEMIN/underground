# Start an agent session

The owner opens the agent's shell in his Tern app (remote host `ugagent@127.0.0.1:18376`, served by the `com.underground.agent-tern` daemon) and types `omp`. The Tern shell's zsh files (`code/zsh`) load the agent environment and put `code/session-bin` first on `PATH`, so `omp` is `code/session-bin/omp`, a link to `code/agent-start`. `agent-start` never changes the folder: omp starts where the owner typed it. Before omp opens, it adds warning notices for a missing or old backup (from `root/status/backup-last`), a pending or failed nightly dream, agent-check findings, a failed background fetch, a main checkout that did not move, and cleanup items it kept. When the folder belongs to a clone at `~/work/<owner>/<name>` (its main checkout or a linked worktree) whose origin is `https://github.com/<owner>/<name>(.git)`, it also syncs that clone in the background: the main checkout moves to origin's default branch only when it is detached or on the default branch with no tracked changes, `.git/ug-fetch.status` records `ok <epoch>` or `failed <epoch>`, and idle worktrees and branches that origin already holds are removed. Any other folder starts omp with no sync and no clone.

## Sub-features

- `ss-tern-shell` the Tern shell's zsh files make `omp` resolve to `code/session-bin/omp`, and arguments after `omp` reach omp.
- `ss-plain` a folder outside any clone (for example the agent home): omp starts there, no sync.
- `ss-backup-none` no `root/status/backup-last`: notice `no good backup yet; read ~/.local/share/underground/backup/backup.log in the owner account`.
- `ss-backup-old` a `status/backup-last` older than 2 days: notice `the last good backup is N days old; read ~/.local/share/underground/backup/backup.log in the owner account`.
- `ss-backup-fresh` a fresh `status/backup-last`: no backup notice.
- `ss-dream-pending` shows `dream: <summary> say "review the dream" to review.` for a pending dream report, and no notice for an old reviewed report.
- `ss-dream-failed` shows `the last dream failed: <reason>; read <file>` for a `failed:` last line in `agent-dream.log` or a `Failure:` line in the newest report.
- `ss-check` shows one notice per agent-check finding: missing agent-config files, wrong or unset omp settings, or unreadable settings.
- `ss-fetch` a start in the main checkout moves it to origin's new commit in the background and writes `.git/ug-fetch.status` `ok <epoch>`.
- `ss-worktree` a start in a linked worktree (or a folder inside it) of the clone syncs the clone; omp starts in the worktree folder, and the worktree does not move.
- `ss-other-origin` a repo under `~/work` whose origin is not GitHub (or a repo outside `~/work`) does not sync: no `.git/ug-fetch.*` files.
- `ss-guard-changes` a main checkout with tracked changes does not move; the next start shows `the main checkout of <repo> has uncommitted changes, so it did not move to origin/main`.
- `ss-guard-branch` a main checkout on another branch does not move; the next start shows `the main checkout of <repo> is on the branch <branch>, so it did not move to origin/main`.
- `ss-fetch-failed` records `failed <epoch>` and shows `the last background fetch of <repo> failed: <last log line>` on the next start only.
- `ss-sweep` removes idle merged worktrees and branches, keeps idle unpushed work and open-PR branches, and shows `cleanup of <repo> kept N items ...` on the next start.

## How to get to it (user POV)

- The owner adds the remote host `ugagent@127.0.0.1:18376` in Tern (once; `host/bin/ug-setup` trusts its host key), or `ugagent@<mac tailscale ip>:18376` on his phone, opens its shell, `cd`s to a folder and types `omp [ARGS...]`.
- In the stand-in, play the Tern shell as the agent: `$U agent "$RUN" --cwd <folder under $B> -- code/session-bin/omp [ARGS...]`. For the zsh path itself, run `/bin/zsh -i -c 'omp ...'` with `ZDOTDIR` set to the stand-in's `root/code/zsh`, as `code/agent-tern` sets it.

## Driving it with ugv

Preconditions:

- Fresh stand-in, from the repo root: `U=.omp/skills/verify-underground/scripts/ugv; RUN=$(date +%Y%m%d-%H%M%S)-session-start; B=/private/tmp/ugv-$RUN; $U up "$RUN"; $U doctor "$RUN"` ends with `doctor: ok`.
- The baseline has no `root/status/backup-last`, so every start shows the `no good backup yet` notice until the backup bullets seed it. Ignore it in the other bullets.
- Notices are proven in the step stdout as `omp-stub: warning notice: <line>` and in the step's `omp` call note `UG_NOTICES=...`.
- `--cwd` is relative to `$B`; the agent's default cwd is `agent-home`.
- The background sync outlives the `ugv agent` step. Before each `look` at the clone, wait for it: `while pgrep -f "$B/agent-home/work/acme/widget" >/dev/null; do sleep 0.2; done`. Its stub calls (`gh pr list`) land in the next step or in `$U calls "$RUN" gh`.

- **Tern shell (`ss-tern-shell`, `ss-plain`, `ss-backup-none`).** Run `$U agent "$RUN" --label ss-tern-shell --env ZDOTDIR=$B/root/code/zsh -- /bin/zsh -i -c 'command -v omp; omp --model x/y'`. Exit `0`; stdout `$B/root/code/session-bin/omp`, `omp-stub: session started in $B/agent-home` and `omp-stub: warning notice: no good backup yet; read ~/.local/share/underground/backup/backup.log in the owner account`; the omp session call argv is `--extension $B/root/code/ug-notices.ts --model x/y` with `HOME=$B/agent-home` and `UG_GATEWAY_TOKEN=set`.
- **Plain start.** Run `$U agent "$RUN" --label ss-plain -- code/session-bin/omp`. Exit `0`; `omp-stub: session started in $B/agent-home` and only the backup notice; the only stub calls are `omp config list --json` (agent-check) and the session call.
- **Backup 3 days old (`ss-backup-old`).** Run `$U look "$RUN" ss-backup-old-seed -- /bin/sh -c 'printf "%s\n" $(( $(date +%s) - 3*86400 - 60 )) >root/status/backup-last; cat root/status/backup-last'`, then `$U agent "$RUN" --label ss-backup-old -- code/session-bin/omp`. Stdout has `omp-stub: warning notice: the last good backup is 3 days old; read ~/.local/share/underground/backup/backup.log in the owner account`.
- **Fresh backup (`ss-backup-fresh`).** Run `$U look "$RUN" ss-backup-fresh-seed -- /bin/sh -c 'date +%s >root/status/backup-last; cat root/status/backup-last'`, then `$U agent "$RUN" --label ss-backup-fresh -- code/session-bin/omp`. Stdout is only `omp-stub: session started in $B/agent-home`; the omp note reads `UG_NOTICES=''`. Keep this file; the later bullets then show only their own notices.
- **Pending dream.** Seed a pending report dated yesterday, then start. Run `mkdir -p $B/agent-home/.omp/agent/dreams; printf '# Dream 2026-11-20\n\nStatus: pending\nSummary: merged 3 duplicate memories.\n' > $B/agent-home/.omp/agent/dreams/2026-11-20.md; touch -t 202001010300 $B/agent-home/.omp/agent/dreams/2026-11-20.md`, then `$U look "$RUN" ss-dream-pending-seed -- cat agent-home/.omp/agent/dreams/2026-11-20.md` and `$U agent "$RUN" --label ss-dream-pending -- code/session-bin/omp`. Exit `0`; stdout has `omp-stub: warning notice: dream: merged 3 duplicate memories. say "review the dream" to review.`
- **Reviewed dream.** Mark the old report reviewed. Run `sed -i '' 's/^Status: pending/Status: reviewed/' $B/agent-home/.omp/agent/dreams/2026-11-20.md; touch -t 202001010300 $B/agent-home/.omp/agent/dreams/2026-11-20.md`, then `$U agent "$RUN" --label ss-dream-reviewed -- code/session-bin/omp`. No notice.
- **Failed dream, log.** Make the last `agent-dream.log` line a failure. Run `printf '2026-11-21T03:00:00Z started\n2026-11-21T03:04:00Z failed: omp -p exited 1\n' > $B/root/logs/agent-dream.log`, then `$U look "$RUN" ss-dream-failed-log-seed -- tail -n 1 root/logs/agent-dream.log` and `$U agent "$RUN" --label ss-dream-failed-log -- code/session-bin/omp`. Stdout has `omp-stub: warning notice: the last dream failed: omp -p exited 1; read $B/root/logs/agent-dream.log`.
- **Failed dream, report.** Clear the log failure and add a newer report with a `Failure:` line. Run `printf '2026-11-21T03:00:00Z started\n2026-11-21T03:05:00Z ok\n' > $B/root/logs/agent-dream.log; printf '# Dream 2026-11-21\n\nStatus: pending\nFailure: the model answer had no Summary line\n' > $B/agent-home/.omp/agent/dreams/2026-11-21.md`, then `$U look "$RUN" ss-dream-failed-report-seed -- cat agent-home/.omp/agent/dreams/2026-11-21.md` and `$U agent "$RUN" --label ss-dream-failed-report -- code/session-bin/omp`. Stdout has `omp-stub: warning notice: the last dream failed: the model answer had no Summary line; read $B/agent-home/.omp/agent/dreams/2026-11-21.md` and no `dream:` summary notice. Then park the report: `mv $B/agent-home/.omp/agent/dreams/2026-11-21.md $B/dream-2026-11-21.parked`.
- **Agent-check findings.** Break two settings and move a required file away. Run `/usr/bin/jq '."memory.backend".value="local" | del(."skills.enabled".value)' $B/fixtures/omp-config.json > $B/fixtures/c.json && mv $B/fixtures/c.json $B/fixtures/omp-config.json; mv $B/agent-home/.omp/agent/extensions/underground-guard.ts $B/guard.parked`, then `$U look "$RUN" ss-check-seed -- ls agent-home/.omp/agent/extensions` and `$U agent "$RUN" --label ss-check -- code/session-bin/omp`. Stdout has three notices: `~/.omp/agent/extensions/underground-guard.ts is missing; underground needs it: this extension blocks destructive commands of the agent. add it to your agent-config`, `memory.backend is local; underground needs mnemopi: the nightly dream reviews and consolidates the agent's mnemopi memory. set it in your agent-config config.yml` and `skills.enabled is unset; underground needs true: ... set it in your agent-config config.yml`.
- **Unreadable settings.** Make `omp config list` fail. Run `$U fault "$RUN" omp-config 1`, then `$U agent "$RUN" --label ss-check-unreadable -- code/session-bin/omp`. The settings notices become one: `agent-check cannot read the omp settings (omp config list failed), so 5 settings that underground needs are not checked`; the missing-file notice stays. The session still opens (exit `0`).
- **Check restored.** Run `$U fault "$RUN" omp-config clear; mv $B/guard.parked $B/agent-home/.omp/agent/extensions/underground-guard.ts; /usr/bin/jq '."memory.backend".value="mnemopi" | ."skills.enabled".value="true"' $B/fixtures/omp-config.json > $B/fixtures/c.json && mv $B/fixtures/c.json $B/fixtures/omp-config.json`, then `$U agent "$RUN" --label ss-check-restored -- code/session-bin/omp`. No notice.
- **Background fetch (`ss-fetch`).** Make a repo, push a second commit to origin, start in the clone. Run `$U repo "$RUN" acme/widget; $U git "$RUN" -- -C seeds/acme/widget commit --allow-empty -qm 'seed: second commit'; $U git "$RUN" -- -C seeds/acme/widget push -q origin main`, then `$U look "$RUN" ss-fetch-before -- git -C agent-home/work/acme/widget log -1 --format='%h %s'` (`seed: first commit`, no `.git/ug-fetch.status`), then `$U agent "$RUN" --label ss-fetch --cwd agent-home/work/acme/widget -- code/session-bin/omp`. Exit `0`; stdout `omp-stub: session started in $B/agent-home/work/acme/widget`. Wait for the sync, then run `$U look "$RUN" ss-fetch-after -- /bin/sh -c 'cat agent-home/work/acme/widget/.git/ug-fetch.status; git -C agent-home/work/acme/widget log -1 --format="%h %s"'`: `ok <epoch>` and `seed: second commit`. `$U calls "$RUN" gh` shows `pr list -R acme/widget --state open ...`.
- **Linked worktree (`ss-worktree`).** Add a worktree at the old tip, push a third commit, start inside the worktree. Run `$U git "$RUN" -- -C agent-home/work/acme/widget worktree add -q -b feat $B/agent-home/wt/feat HEAD; $U git "$RUN" -- -C seeds/acme/widget commit --allow-empty -qm 'seed: third commit'; $U git "$RUN" -- -C seeds/acme/widget push -q origin main`, then `$U agent "$RUN" --label ss-worktree --cwd agent-home/wt/feat -- code/session-bin/omp`. Exit `0`; stdout `omp-stub: session started in $B/agent-home/wt/feat`. Wait, then `$U look "$RUN" ss-worktree-after -- /bin/sh -c 'git -C agent-home/work/acme/widget log -1 --format=%s; git -C agent-home/wt/feat log -1 --format=%s'`: `seed: third commit` (the clone moved) and `seed: second commit` (the worktree did not).
- **Other origin (`ss-other-origin`).** Run `$U git "$RUN" -- init -q -b main agent-home/work/acme/local; $U git "$RUN" -- -C agent-home/work/acme/local remote add origin https://gitlab.com/acme/local.git`, then `$U agent "$RUN" --label ss-other-origin --cwd agent-home/work/acme/local -- code/session-bin/omp`. Exit `0`; `omp-stub: session started in $B/agent-home/work/acme/local`, no notice. Run `$U look "$RUN" ss-other-origin-after -- ls -A agent-home/work/acme/local/.git`: no `ug-fetch.*` file.
- **Tracked change (`ss-guard-changes`).** Change a tracked file in the main checkout and push a fourth commit. Run `$U look "$RUN" ss-guard-seed -- /bin/sh -c 'printf "change\n" >agent-home/work/acme/widget/README.md'; $U git "$RUN" -- -C seeds/acme/widget commit --allow-empty -qm 'seed: fourth commit'; $U git "$RUN" -- -C seeds/acme/widget push -q origin main`, then `$U agent "$RUN" --label ss-guard --cwd agent-home/work/acme/widget -- code/session-bin/omp`. Wait, then `$U look "$RUN" ss-guard-after -- /bin/sh -c 'git -C agent-home/work/acme/widget log -1 --format=%s; cat agent-home/work/acme/widget/README.md agent-home/work/acme/widget/.git/ug-reset.summary'`: `seed: third commit`, `change`, `the main checkout of acme/widget has uncommitted changes, so it did not move to origin/main`. The next start, `$U agent "$RUN" --label ss-guard-next --cwd agent-home/work/acme/widget -- code/session-bin/omp`, shows that line as a notice. Wait, then undo the change with `$U git "$RUN" -- -C agent-home/work/acme/widget checkout -q -- README.md`.
- **Other branch (`ss-guard-branch`).** Run `$U git "$RUN" -- -C agent-home/work/acme/widget checkout -q -b topic`, then `$U agent "$RUN" --label ss-guard-branch --cwd agent-home/work/acme/widget -- code/session-bin/omp`. Wait, then `$U look "$RUN" ss-guard-branch-after -- /bin/sh -c 'git -C agent-home/work/acme/widget log -1 --format=%s; cat agent-home/work/acme/widget/.git/ug-reset.summary'`: `seed: third commit` and `the main checkout of acme/widget is on the branch topic, so it did not move to origin/main`. Run `$U git "$RUN" -- -C agent-home/work/acme/widget checkout -q main` and `$U agent "$RUN" --label ss-guard-clear --cwd agent-home/work/acme/widget -- code/session-bin/omp` (it shows the branch notice once), wait, then `$U look "$RUN" ss-guard-clear-after -- git -C agent-home/work/acme/widget log -1 --format=%s`: `seed: fourth commit`.
- **Failed fetch (`ss-fetch-failed`).** Hide the origin and push a fifth commit. Run `$U git "$RUN" -- -C seeds/acme/widget commit --allow-empty -qm 'seed: fifth commit'; $U git "$RUN" -- -C seeds/acme/widget push -q origin main; mv $B/origins/acme/widget.git $B/origins/acme/widget.git.away`, then `$U agent "$RUN" --label ss-fetch-failed --cwd agent-home/work/acme/widget -- code/session-bin/omp`. That start shows no fetch notice. Wait, then `$U look "$RUN" ss-fetch-failed-after -- /bin/sh -c 'cat agent-home/work/acme/widget/.git/ug-fetch.status; git -C agent-home/work/acme/widget log -1 --format="%h %s"; tail -n 1 agent-home/work/acme/widget/.git/ug-fetch.log'`: `failed <epoch>`, still `seed: fourth commit`, last log line `and the repository exists.`
- **Failed fetch, next start.** Run `$U agent "$RUN" --label ss-fetch-failed-next --cwd agent-home/work/acme/widget -- code/session-bin/omp`. Stdout has `omp-stub: warning notice: the last background fetch of acme/widget failed: and the repository exists.` Wait for the sync.
- **Fetch recovers.** Run `mv $B/origins/acme/widget.git.away $B/origins/acme/widget.git; $U agent "$RUN" --label ss-fetch-recover --cwd agent-home/work/acme/widget -- code/session-bin/omp`. This start still shows the failure notice (it reports the previous fetch). Wait, then `$U look "$RUN" ss-fetch-recovered -- /bin/sh -c 'cat agent-home/work/acme/widget/.git/ug-fetch.status; git -C agent-home/work/acme/widget log -1 --format="%h %s"'`: `ok <epoch>` and `seed: fifth commit`.
- **Cleanup sweep (`ss-sweep`).** Add four worktrees and two branches, age all but `fresh` past 3 days, mark `review` as an open PR. Run `C=agent-home/work/acme/widget; G=$B/$C/.git; for w in old uniq fresh review; do $U git "$RUN" -- -C $C worktree add -q -b $w $B/agent-home/wt/$w origin/main; done; echo 'only here' > $B/agent-home/wt/uniq/u; $U git "$RUN" -- -C agent-home/wt/uniq add u; $U git "$RUN" -- -C agent-home/wt/uniq commit -qm unique; echo 'in review' > $B/agent-home/wt/review/r; $U git "$RUN" -- -C agent-home/wt/review add r; $U git "$RUN" -- -C agent-home/wt/review commit -qm review; $U git "$RUN" -- -C $C branch stale origin/main; $U git "$RUN" -- -C $C branch lone uniq; printf '7 review\n' > $B/fixtures/gh-pr-list; for w in old uniq review; do touch -t 202001010000 $G/worktrees/$w/HEAD $G/worktrees/$w/index $G/worktrees/$w/logs/HEAD $G/logs/refs/heads/$w; done; touch -t 202001010000 $G/logs/refs/heads/stale $G/logs/refs/heads/lone`, then `$U look "$RUN" ss-sweep-before -- /bin/sh -c "git -C $C worktree list; git -C $C branch"`, then `$U agent "$RUN" --label ss-sweep --cwd agent-home/work/acme/widget -- code/session-bin/omp`. That start shows no cleanup notice. Wait, then `$U look "$RUN" ss-sweep-after -- /bin/sh -c "git -C $C worktree list; git -C $C branch; tail -n 3 $C/.git/ug-fetch.log; cat $C/.git/ug-clean.summary"`: the `old` worktree and branch and `stale` are gone; `fresh`, `review`, `uniq`, `lone` and the recent `topic` (and `feat`) stay; `.git/ug-fetch.log` ends `cleanup: removed the worktree $B/agent-home/wt/old`, `cleanup: deleted the branch old`, `cleanup: deleted the branch stale`; `.git/ug-clean.summary` reads `cleanup of acme/widget kept 2 items idle for 3 days with work that GitHub does not hold; push or delete them: $B/agent-home/wt/uniq lone`.
- **Kept items, next start.** Run `$U agent "$RUN" --label ss-sweep-kept --cwd agent-home/work/acme/widget -- code/session-bin/omp`. Stdout has `omp-stub: warning notice: cleanup of acme/widget kept 2 items idle for 3 days with work that GitHub does not hold; push or delete them: $B/agent-home/wt/uniq lone`. Wait for the sync.
- **Sweep without PR list.** Run `$U fault "$RUN" gh 1; $U agent "$RUN" --label ss-sweep-gh-fail --cwd agent-home/work/acme/widget -- code/session-bin/omp`, wait, then `$U look "$RUN" ss-sweep-gh-fail-after -- cat agent-home/work/acme/widget/.git/ug-fetch.status agent-home/work/acme/widget/.git/ug-clean.summary`: `ok <epoch>` and `cleanup of acme/widget skipped: cannot list its open pull requests`. Then `$U agent "$RUN" --label ss-sweep-gh-fail-next --cwd agent-home/work/acme/widget -- code/session-bin/omp` shows that line as a notice. Run `$U fault "$RUN" gh clear`.
- **Finish.** Run `$U down "$RUN"`; it prints `evidence: $HOME/scratch/verify-underground/$RUN`.

## Gotchas

- `agent-start` compares the physical cwd that git reports with `$HOME/work`. In the stand-in both live under `/private/tmp`, so they match; a recipe that builds its own clone through a symlinked path would not sync.
- `ugv up` writes `$B/agent-home/.gitconfig` with `insteadOf = https://github.com/` → `$B/origins/`, so the clone's GitHub origin fetches offline from the bare repo. Do not overwrite that file; without it the fetch would reach the network. To fail a fetch, move the bare repo away (as above). A non-GitHub origin URL does not fail the fetch: it stops the sync.
- `agent-start` never clones: a repo the agent does not have yet must be cloned by the agent itself, and `omp` in a folder that is not a clone just starts omp there.
- The fetch-failure, reset and kept-items notices describe the previous background sync. The start that runs the sync shows nothing, and the first start after a fix still shows the old notice.
- The failed-fetch notice quotes only the last line of `.git/ug-fetch.log`. For git errors that is `and the repository exists.`, which does not name the cause. Read the whole log.
- The reset guard counts tracked changes only (`git status --untracked-files=no`); an untracked file in the main checkout does not stop the move.
- A dream report newer than 24 h with no `Status:` line shows its `Summary:`. Once every proposal has a status other than `pending`, it shows nothing. Age the file with `touch -t`, or mark a proposal decided, to test the reviewed case.
- The newest report is chosen by file time, not by name. Park old reports with `mv`, or a stale `Failure:` report hides a newer one.
- The backup age is whole days, rounded down, and the notice starts above 2 days (172800 s). Seed 3 days plus a margin, as above.
- Sweep ageing needs all of the worktree's `HEAD`, `index`, `logs/HEAD` and `logs/refs/heads/<branch>` aged. Any `git` command that touches the worktree after `touch -t` makes it fresh again.
- `ss-check` uses `$B/fixtures/omp-config.json`. Restore it, or every later start carries setting notices.
- `/bin/zsh -i` in a step has no terminal; it is only a proof that the zsh files resolve `omp`. The Tern daemon itself (`code/agent-tern`, rendered but never run) is not in the stand-in.
- Always wait for the background sync before a `look`, or the status file is missing or from the previous run. `ugv down` also waits up to 5 s for it.
