# Session start notices and repo sync

Each agent session starts with `code/agent-start`, which the owner's `omp` launcher (`host/bin/ug-agent`) reaches through the agent sshd. Before the omp session opens it adds warning notices for a pending or failed nightly dream, for agent-check findings, for a failed background fetch, and for cleanup items it kept. With a repo it clones that repo on first use (blocking, exit `69` on failure), or else starts the omp session in the existing clone and fetches in the background: the main checkout moves to origin's default branch, `.git/ug-fetch.status` records `ok <epoch>` or `failed <epoch>`, and idle worktrees and branches that origin already holds are removed.

## Sub-features

- `ss-plain` starts the session in `~/scratch` when no repo is given, and passes the owner's notices through.
- `ss-dream-pending` shows `dream: <summary> say "review the dream" to review.` for a pending dream report, and no notice for an old reviewed report.
- `ss-dream-failed` shows `the last dream failed: <reason>; read <file>` for a `failed:` last line in `agent-dream.log` or a `Failure:` line in the newest report.
- `ss-check` shows one notice per agent-check finding: missing agent-config files, wrong or unset omp settings, or unreadable settings.
- `ss-fetch` moves the existing clone to origin's new commit in the background and writes `.git/ug-fetch.status` `ok <epoch>`.
- `ss-fetch-failed` records `failed <epoch>` and shows `the last background fetch of <repo> failed: <last log line>` on the next start only.
- `ss-clone` clones a repo the agent does not have yet before omp starts; a failed first fetch exits `69`.
- `ss-sweep` removes idle merged worktrees and branches, keeps idle unpushed work and open-PR branches, and shows `cleanup of <repo> kept N items ...` on the next start.
- `ss-bad-repo` refuses a `UG_REPO` that is not `owner/name` with exit `1`.

## How to get to it (user POV)

- The owner runs `omp` (`host/bin/ug-agent`) outside a git checkout: no repo, the session opens in `~/scratch`.
- The owner runs `omp` inside a checkout whose origin is a GitHub URL: the launcher sends `UG_REPO=<owner>/<name>` and the session opens in `~/work/<owner>/<name>`.
- The agent sshd's forced command (`code/agent-session`) runs `code/agent-start` for every agent login; drive it directly as `$U agent "$RUN" --env UG_REPO=<owner>/<name> -- code/agent-start` for agent-side detail.

## Driving it with ugv

Preconditions:

- Fresh stand-in, from the repo root: `U=.omp/skills/verify-underground/scripts/ugv; RUN=$(date +%Y%m%d-%H%M%S)-session-start; B=/private/tmp/ugv-$RUN; $U up "$RUN"; $U doctor "$RUN"` ends with `doctor: ok`.
- The baseline has no backup, so every owner-launched start also shows `no good backup yet; read $B/owner-home/.local/share/underground/backup/backup.log` (see [launch-agent.md](./launch-agent.md)). Ignore it here.
- Notices are proven in the step stdout as `omp-stub: warning notice: <line>` and in the step's `omp` call note `UG_NOTICES=...`. Notices made by `agent-start` are not in the `ssh` call note, which holds only what the owner side sent.
- The background fetch outlives the `ugv owner` step. Before each `look` at the clone, wait for it: `while pgrep -f "$B/agent-home/work/acme/widget" >/dev/null; do sleep 0.2; done`. Its stub calls (`gh pr list`) land in the next step or in `$U calls "$RUN" gh`.

- **Plain start.** The owner runs `omp` outside a repo. Run `$U owner "$RUN" --label ss-plain -- host/bin/ug-agent`. Exit `0`; stdout `omp-stub: session started in $B/agent-home/scratch` and only the backup notice; the `ssh` and `omp` call notes both read `UG_REPO=<unset>`. Run `$U look "$RUN" ss-plain -- ls -d agent-home/scratch` to see the session dir exists.
- **Pending dream.** Seed a pending report dated yesterday, then start. Run `mkdir -p $B/agent-home/.omp/agent/dreams; printf '# Dream 2026-11-20\n\nStatus: pending\nSummary: merged 3 duplicate memories.\n' > $B/agent-home/.omp/agent/dreams/2026-11-20.md; touch -t 202001010300 $B/agent-home/.omp/agent/dreams/2026-11-20.md`, then `$U look "$RUN" ss-dream-pending-seed -- cat agent-home/.omp/agent/dreams/2026-11-20.md` and `$U owner "$RUN" --label ss-dream-pending -- host/bin/ug-agent`. Exit `0`; stdout has `omp-stub: warning notice: dream: merged 3 duplicate memories. say "review the dream" to review.`
- **Reviewed dream.** Mark the old report reviewed. Run `sed -i '' 's/^Status: pending/Status: reviewed/' $B/agent-home/.omp/agent/dreams/2026-11-20.md; touch -t 202001010300 $B/agent-home/.omp/agent/dreams/2026-11-20.md`, then `$U owner "$RUN" --label ss-dream-reviewed -- host/bin/ug-agent`. Only the backup notice appears.
- **Failed dream, log.** Make the last `agent-dream.log` line a failure. Run `printf '2026-11-21T03:00:00Z started\n2026-11-21T03:04:00Z failed: omp -p exited 1\n' > $B/root/logs/agent-dream.log`, then `$U look "$RUN" ss-dream-failed-log-seed -- tail -n 1 root/logs/agent-dream.log` and `$U owner "$RUN" --label ss-dream-failed-log -- host/bin/ug-agent`. Stdout has `omp-stub: warning notice: the last dream failed: omp -p exited 1; read $B/root/logs/agent-dream.log`.
- **Failed dream, report.** Clear the log failure and add a newer report with a `Failure:` line. Run `printf '2026-11-21T03:00:00Z started\n2026-11-21T03:05:00Z ok\n' > $B/root/logs/agent-dream.log; printf '# Dream 2026-11-21\n\nStatus: pending\nFailure: the model answer had no Summary line\n' > $B/agent-home/.omp/agent/dreams/2026-11-21.md`, then `$U look "$RUN" ss-dream-failed-report-seed -- cat agent-home/.omp/agent/dreams/2026-11-21.md` and `$U owner "$RUN" --label ss-dream-failed-report -- host/bin/ug-agent`. Stdout has `omp-stub: warning notice: the last dream failed: the model answer had no Summary line; read $B/agent-home/.omp/agent/dreams/2026-11-21.md` and no `dream:` summary notice. Then park the report: `mv $B/agent-home/.omp/agent/dreams/2026-11-21.md $B/dream-2026-11-21.parked`.
- **Agent-check findings.** Break two settings and move a required file away. Run `/usr/bin/jq '."memory.backend".value="local" | del(."skills.enabled".value)' $B/fixtures/omp-config.json > $B/fixtures/c.json && mv $B/fixtures/c.json $B/fixtures/omp-config.json; mv $B/agent-home/.omp/agent/extensions/underground-guard.ts $B/guard.parked`, then `$U look "$RUN" ss-check-seed -- ls agent-home/.omp/agent/extensions` and `$U owner "$RUN" --label ss-check -- host/bin/ug-agent`. Stdout has three notices: `~/.omp/agent/extensions/underground-guard.ts is missing; underground needs it: this extension blocks destructive commands of the agent. add it to your agent-config`, `memory.backend is local; underground needs mnemopi: the nightly dream reviews and consolidates the agent's mnemopi memory. set it in your agent-config config.yml` and `skills.enabled is unset; underground needs true: ... set it in your agent-config config.yml`.
- **Unreadable settings.** Make `omp config list` fail. Run `$U fault "$RUN" omp-config 1`, then `$U owner "$RUN" --label ss-check-unreadable -- host/bin/ug-agent`. The settings notices become one: `agent-check cannot read the omp settings (omp config list failed), so 5 settings that underground needs are not checked`; the missing-file notice stays. The session still opens (exit `0`).
- **Check restored.** Run `$U fault "$RUN" omp-config clear; mv $B/guard.parked $B/agent-home/.omp/agent/extensions/underground-guard.ts; /usr/bin/jq '."memory.backend".value="mnemopi" | ."skills.enabled".value="true"' $B/fixtures/omp-config.json > $B/fixtures/c.json && mv $B/fixtures/c.json $B/fixtures/omp-config.json`, then `$U owner "$RUN" --label ss-check-restored -- host/bin/ug-agent`. Only the backup notice appears.
- **Background fetch.** Make a repo, push a second commit to origin, start from the owner checkout. Run `$U repo "$RUN" acme/widget; $U git "$RUN" -- -C seeds/acme/widget commit --allow-empty -qm 'seed: second commit'; $U git "$RUN" -- -C seeds/acme/widget push -q origin main`, then `$U look "$RUN" ss-fetch-before -- git -C agent-home/work/acme/widget log -1 --format='%h %s'` (`seed: first commit`, no `.git/ug-fetch.status`), then `$U owner "$RUN" --label ss-fetch --cwd owner-home/code/widget -- host/bin/ug-agent`. Exit `0`; stdout `omp-stub: session started in $B/agent-home/work/acme/widget`; `ssh` and `omp` notes `UG_REPO=acme/widget`. Wait for the fetch, then run `$U look "$RUN" ss-fetch-after -- /bin/sh -c 'cat agent-home/work/acme/widget/.git/ug-fetch.status; git -C agent-home/work/acme/widget log -1 --format="%h %s"'`: `ok <epoch>` and `seed: second commit`. `$U calls "$RUN" gh` shows `pr list -R acme/widget --state open ...`.
- **Failed fetch.** Point the clone's origin nowhere, push a third commit. Run `$U git "$RUN" -- -C agent-home/work/acme/widget remote set-url origin /nonexistent; $U git "$RUN" -- -C seeds/acme/widget commit --allow-empty -qm 'seed: third commit'; $U git "$RUN" -- -C seeds/acme/widget push -q origin main`, then `$U owner "$RUN" --label ss-fetch-failed --cwd owner-home/code/widget -- host/bin/ug-agent`. That start shows no fetch notice. Wait, then `$U look "$RUN" ss-fetch-failed-after -- /bin/sh -c 'cat agent-home/work/acme/widget/.git/ug-fetch.status; git -C agent-home/work/acme/widget log -1 --format="%h %s"; tail -n 1 agent-home/work/acme/widget/.git/ug-fetch.log'`: `failed <epoch>`, still `seed: second commit`, last log line `and the repository exists.`
- **Failed fetch, next start.** Run `$U owner "$RUN" --label ss-fetch-failed-next --cwd owner-home/code/widget -- host/bin/ug-agent`. Stdout has `omp-stub: warning notice: the last background fetch of acme/widget failed: and the repository exists.` Wait for the fetch.
- **Fetch recovers.** Run `$U git "$RUN" -- -C agent-home/work/acme/widget remote set-url origin $B/origins/acme/widget.git; $U owner "$RUN" --label ss-fetch-recover --cwd owner-home/code/widget -- host/bin/ug-agent`. This start still shows the failure notice (it reports the previous fetch). Wait, then `$U look "$RUN" ss-fetch-recovered -- /bin/sh -c 'cat agent-home/work/acme/widget/.git/ug-fetch.status; git -C agent-home/work/acme/widget log -1 --format="%h %s"'`: `ok <epoch>` and `seed: third commit`.
- **Cleanup sweep.** Add four worktrees and two branches, age all but `fresh` past 3 days, mark `review` as an open PR. Run `C=agent-home/work/acme/widget; G=$B/$C/.git; for w in old uniq fresh review; do $U git "$RUN" -- -C $C worktree add -q -b $w $B/agent-home/wt/$w origin/main; done; echo 'only here' > $B/agent-home/wt/uniq/u; $U git "$RUN" -- -C agent-home/wt/uniq add u; $U git "$RUN" -- -C agent-home/wt/uniq commit -qm unique; echo 'in review' > $B/agent-home/wt/review/r; $U git "$RUN" -- -C agent-home/wt/review add r; $U git "$RUN" -- -C agent-home/wt/review commit -qm review; $U git "$RUN" -- -C $C branch stale origin/main; $U git "$RUN" -- -C $C branch lone uniq; printf '7 review\n' > $B/fixtures/gh-pr-list; for w in old uniq review; do touch -t 202001010000 $G/worktrees/$w/HEAD $G/worktrees/$w/index $G/worktrees/$w/logs/HEAD $G/logs/refs/heads/$w; done; touch -t 202001010000 $G/logs/refs/heads/stale $G/logs/refs/heads/lone`, then `$U look "$RUN" ss-sweep-before -- /bin/sh -c "git -C $C worktree list; git -C $C branch"` (worktrees `fresh old review uniq`, branches `fresh lone main old review stale uniq`), then `$U owner "$RUN" --label ss-sweep --cwd owner-home/code/widget -- host/bin/ug-agent`. That start shows no cleanup notice. Wait, then `$U look "$RUN" ss-sweep-after -- /bin/sh -c "git -C $C worktree list; git -C $C branch; tail -n 3 $C/.git/ug-fetch.log; cat $C/.git/ug-clean.summary"`: `old` worktree and branch and `stale` are gone, `fresh`, `review`, `uniq`, `lone` stay; `.git/ug-fetch.log` ends `cleanup: removed the worktree $B/agent-home/wt/old`, `cleanup: deleted the branch old`, `cleanup: deleted the branch stale`; `.git/ug-clean.summary` reads `cleanup of acme/widget kept 2 items idle for 3 days with work that GitHub does not hold; push or delete them: $B/agent-home/wt/uniq lone`.
- **Kept items, next start.** Run `$U owner "$RUN" --label ss-sweep-kept --cwd owner-home/code/widget -- host/bin/ug-agent`. Stdout has `omp-stub: warning notice: cleanup of acme/widget kept 2 items idle for 3 days with work that GitHub does not hold; push or delete them: $B/agent-home/wt/uniq lone`. Wait for the fetch.
- **Sweep without PR list.** Run `$U fault "$RUN" gh 1; $U owner "$RUN" --label ss-sweep-gh-fail --cwd owner-home/code/widget -- host/bin/ug-agent`, wait, then `$U look "$RUN" ss-sweep-gh-fail-after -- cat agent-home/work/acme/widget/.git/ug-fetch.status agent-home/work/acme/widget/.git/ug-clean.summary`: `ok <epoch>` and `cleanup of acme/widget skipped: cannot list its open pull requests`. Then `$U owner "$RUN" --label ss-sweep-gh-fail-next --cwd owner-home/code/widget -- host/bin/ug-agent` shows that line as a notice. Run `$U fault "$RUN" gh clear`.
- **Agent-side start.** Run `$U agent "$RUN" --label ss-agent-direct --env UG_REPO=acme/widget -- code/agent-start`. Exit `0`; `omp-stub: session started in $B/agent-home/work/acme/widget`; no `no good backup yet` notice (owner notices come only from the launcher). The only notice is the one `agent-start` made itself from the previous fetch, here `cleanup of acme/widget skipped: cannot list its open pull requests`, because the `ss-sweep-gh-fail-next` fetch also ran under the `gh` fault. Wait for the fetch.
- **First clone.** Make a repo the agent has no clone of. Run `$U repo "$RUN" acme/gizmo; mv $B/agent-home/work/acme/gizmo $B/gizmo-clone.parked`, then `$U look "$RUN" ss-clone-seed -- /bin/sh -c 'cat agent-home/.gitconfig; ls agent-home/work/acme'` (the `ugv up` rewrite `insteadOf = https://github.com/` to `$B/origins/`, and no `gizmo`), then `$U owner "$RUN" --label ss-clone --cwd owner-home/code/gizmo -- host/bin/ug-agent`. Exit `0`; `omp-stub: session started in $B/agent-home/work/acme/gizmo`. Run `$U look "$RUN" ss-clone-after -- /bin/sh -c 'git -C agent-home/work/acme/gizmo log -1 --format="%h %s"; git -C agent-home/work/acme/gizmo remote get-url origin; ls agent-home/work/acme/gizmo/.git | grep ug- || echo none'`: `seed: first commit`, `https://github.com/acme/gizmo.git`, `none` (no background fetch on the first-clone start).
- **First clone fails.** Make an owner checkout whose GitHub repo does not answer. Run `$U git "$RUN" -- clone -q origins/acme/gizmo.git owner-home/code/absent; $U git "$RUN" -- -C owner-home/code/absent remote set-url origin https://github.com/acme/absent.git`, then `$U owner "$RUN" --label ss-clone-fail --cwd owner-home/code/absent -- host/bin/ug-agent`. Exit `69`; stderr ends `agent-start: git fetch origin for acme/absent failed: is the GitHub App installed on it, and does GitHub answer?`; no omp session call. Run `$U look "$RUN" ss-clone-fail-after -- ls -A agent-home/work/acme/absent`: only `.git` is left.
- **Half clone on retry.** Run `$U owner "$RUN" --label ss-clone-retry --cwd owner-home/code/absent -- host/bin/ug-agent`. Exit `0`: the session opens in the empty `$B/agent-home/work/acme/absent` and no clone is attempted again. Wait with `while pgrep -f "$B/agent-home/work/acme/absent" >/dev/null; do sleep 0.2; done`, then `$U look "$RUN" ss-clone-retry-after -- cat agent-home/work/acme/absent/.git/ug-fetch.status`: `failed <epoch>`.
- **Bad repo name.** Run `$U agent "$RUN" --label ss-bad-repo --env UG_REPO=not-a-slug -- code/agent-start`. Exit `1`; stderr `agent-start: UG_REPO has a value that is not owner/name`; no omp session call.
- **Finish.** Run `$U down "$RUN"`; it prints `evidence: $HOME/scratch/verify-underground/$RUN`.

## Gotchas

- The real first clone fetches `https://github.com/<owner>/<name>.git`. `ugv up` writes `$B/agent-home/.gitconfig` with `insteadOf = https://github.com/` → `$B/origins/`, so a `ugv repo` slug clones offline and any other slug (`acme/absent`) fails offline. Do not overwrite that file in a recipe; without it the clone would reach the network. This proves what `agent-start` does with a fetch that works or fails. It does not prove GitHub, the GitHub App token, or private-repo access.
- A failed first clone leaves `~/work/<owner>/<name>/.git` behind. The next start then treats it as a clone: it opens omp in an empty directory with exit `0` and never clones again, and the only sign is a background-fetch failure notice on the start after that. This is current product behavior (`ss-clone-retry`), not a stand-in artifact.
- The failed-fetch notice quotes only the last line of `.git/ug-fetch.log`. For git errors that is `and the repository exists.`, which does not name the cause. Read the whole log.
- The fetch-failure and kept-items notices describe the previous background fetch. The start that runs the failing fetch shows nothing, and the first start after a fix still shows the old failure.
- A dream report newer than 24 h shows its `Summary:` even when it is not `Status: pending`. Age the file with `touch -t` to test the reviewed case.
- The newest report is chosen by file time, not by name. Park old reports with `mv`, or a stale `Failure:` report hides a newer one.
- Sweep ageing needs all of the worktree's `HEAD`, `index`, `logs/HEAD` and `logs/refs/heads/<branch>` aged. Any `git` command that touches the worktree after `touch -t` makes it fresh again.
- `ss-check` uses `$B/fixtures/omp-config.json`. Restore it, or every later start carries setting notices.
- `$U agent "$RUN" -- code/bin/agent-check` without an argument exits `1` with `agent-check: cannot read the requirements file $B/root/code/bin/requirements`. `agent-start` passes `code/requirements` explicitly, so session notices are not affected. See [requirements-check.md](./requirements-check.md).
- Always wait for the background fetch before a `look`, or the status file is missing or from the previous run. `ugv down` also waits up to 5 s for it.
